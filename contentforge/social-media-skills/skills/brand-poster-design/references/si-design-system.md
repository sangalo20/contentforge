# Successful Idiots (SI) — Brand Design System

SI is a DIFFERENT brand from Joe Downs personal (JD). Hosts: Joe Downs + Peter Swain. Site: successfulidiots.ai. Never bleed JD's navy/blue/Inter into SI, or SI's yellow into JD. Tested June 2026 (2 posters + a 4-scene video on Ep29 "60% zero-click" GEO content).

## Brand spine
- **Colors:** yellow `#FDE801`, green `#16A34A` (bright variant `#22DD7A`), near-black navy `#15151F` / `#0A0A0A`, white. Muted grey `#8A8A92` for meta.
- **Fonts:** Oswald (headings, condensed bold caps) + Space Mono (labels/meta) + Open Sans (body). Remotion: `@remotion/google-fonts/Oswald`, `/SpaceMono`, `/OpenSans`.
- **Voice:** third-person brand ("Joe + Peter broke down…"), bold, self-aware, contrarian, AI-for-entrepreneurs. NOT hype ("game changer", "level up", "this is gold" are banned — see successfulidiots-podcast skill).
- **Footer:** `successfulidiots.ai` + "Joe Downs + Peter Swain" or "The Successful Idiots Podcast". Episode tag `EP. 0NN` / `CASE FILE // SI.0NN`.

## TWO proven visual modes (pick per piece)
1. **Dark "CASE FILE" dossier** — near-black bg, dot grid, `CASE FILE //`, `SUBJECT:`, `STATUS:`, green glowing status dot, huge yellow stat number, Space Mono labels, green left-border "FINDING" line. Best for stat / thought-leadership pieces. (The pre-existing `..._60-percent-no-click_v1.html` is the reference template; its big stat uses `font-size:430px` — keep that size but `line-height:0.95` not 0.82, see overflow pitfall.)
2. **Neo-brutalist sticker-pop** — saturated yellow bg + black graph-paper grid, Oswald caps headline with green accent word, hard black borders + offset shadows (`box-shadow: NNpx NNpx 0 <green/navy>`), sticker tags rotated `-2deg`, white/dark split cards (OLD WORLD vs NEW WORLD). Bold, youthful, high-contrast.

## Image generation reality (June 2026)
True AI image-gen (new drawn POSES) was NOT available in this environment: no local ComfyUI, no DALL·E/Imagen MCP, and delegating to the `image_gen` toolset returned no actual image model. So "different poses" of a character (arms crossed, pointing) could NOT be produced — only reuse/recomposition of existing art. If a future session has a real image-gen tool wired up, use the saved reference photos + the character description above with img2img / IP-Adapter to lock likeness. Do NOT fake generated images (never rename SVG/HTML as a generated .png). (This is an environment-capability note, not a permanent "can't do images" rule — recheck tools each session.)

## Pitfalls (SI-specific, from testing)
- Big stat number overflow: same line-height bug as JD — `font-size:430px` needs `line-height ≥ 0.95` + margin on the subtitle, never `0.8/0.82`.
- Empty middle band on character/split layouts (the "looks good but empty" complaint): fill with OLD/NEW bubble cards or a quote band between headline and characters; use `[spacer]` flex only where the gap is intentional.
- Video hook clarity: a small setup tag + huge punch headline reads as ONLY the punch in motion. Make the setup line land FIRST and large enough to register before the punch animates in (Joe: video "missing content … says Reset it rather than AI didn't change search, it reset it").
- Feature BOTH hosts when the piece is about the show — don't default to whichever single host has a usable solo photo (Joe: "why is it only Peter Swain").
- **Concept/diagram visuals: a good IDEA is not enough — the diagram must be instantly LEGIBLE (Joe rejected one on clarity, SI Ep030 "prompt vs system", June 2026).** When you build a hand-authored SVG diagram (nodes/arrows/flow) as the visual vocabulary, Joe will accept the concept but reject muddy execution: *"the idea behind the visual is good… but the visual itself is not well done, it's not clear."* The specific failure modes a node-flow diagram falls into, and the fixes that worked:
  - **Overlapping nodes blur into a blob** → space circles so they never touch; put real GAPS between them.
  - **Arrowheads buried inside the next circle** (look like a notch bitten out, not a connector) → connectors must sit in the GAP between nodes — start each line at the edge of node A and end it short of node B's edge, never under it. Use a small `marker` (markerWidth ~7, refX so the tip lands at the line end).
  - **A zig-zag / multi-direction path is unreadable** → keep ONE dominant flow axis (clean left-to-right on a common baseline). Don't route right→down→right→up; the eye can't follow it.
  - **The "growth/compounding" message is lost** → make it explicit: nodes growing steadily in radius along the axis = growth; a single curved dashed **feedback loop arcing back to the start (labeled, e.g. "FEEDS ITSELF")** = compounding. A contrasting accent color on the loop (yellow over green nodes) separates "flow" from "feedback."
  - **Contrast the two states hard** → the "bad" side should be visibly impoverished (one isolated dark dot + a dotted line that dies at "stops."); the "good" side rich (the growing chain + loop). Scale + completeness carry the meaning, not labels.
  Always vision-QA a diagram specifically for: nodes touching, arrowheads inside circles, an illegible path, and whether the intended message (growth/loop/dead-end) actually reads at a glance. Working example: `gen_ep30_idea1.py` IG poster (v1 muddy → rebuilt clean).\n- **\"The characters' teeth look yellow\" on a YELLOW-background piece = a SCALE/SURROUND artifact, NOT a dirty cutout — DIAGNOSE before \"fixing\" the PNG (Joe caught it on the SI SmartLink avatar, June 2026).** Joe flagged Peter's teeth reading yellow. INSTINCT is to recolor the cutout — WRONG. The teeth in `SI_char_duo_*_T.png` are provably **pure white** (`(255,255,255)`/`(253,253,253)` when you sample them). The yellow look is the bright `#FDE801` background visually contaminating a small white tooth-strip at avatar scale — the eye reads a tiny white sliver swimming in saturated yellow as yellowish. DIAGNOSTIC ORDER (do this for ANY \"the cutout color is wrong\" complaint): (1) open the transparent cutout itself and **read the actual pixel values** in the flagged region with PIL (`px[x,y]`) — sample a band across the teeth/feature; (2) if those pixels are clean (white teeth, correct skin), it is a surround/scale artifact, not a baked-in tint — do NOT global-color-replace (a blanket yellow→white swap destroys the hoodies, which ARE pure yellow `~(253,232,1)`); (3) FIX = put a NEUTRAL surround between the characters and the same-hue background so light features stop borrowing the hue. The proven fix for the avatar: a **solid white spotlight disc** behind the characters (`radial-gradient(circle,#fff 0%,#fff 60%,rgba(255,255,255,.85) 76%,transparent 100%)`, ~760px on a 1080 canvas) — replaced the too-soft `.55`-alpha glow. Teeth then read clean white; grid still shows at the corners.
