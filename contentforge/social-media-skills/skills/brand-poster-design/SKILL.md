# Brand Poster / Graphic Design

End-to-end pipeline for turning a finished post into an on-brand visual that lands on a Metricool draft. Proven working June 2026.

## Golden rules (Joe's brief, locked)
1. **Use the brand's REAL graphic language** — check the live site for graphic style every time, don't design from vibes. Confirm colors/fonts from `brand-knowledge-hub` → `references/live-ids.md` (Brand visual identity table). ⛔ **The APPROVED BUILD beats the doc table when they disagree — Joe caught this TWICE in one session (SM Ep001: wrong slate-blue, then wrong serif-vs-Big-Shoulders font).** The `live-ids.md` Canva-kit rows are a *reference*, not gospel — they have drifted from what's actually on the feed. Before building a brand's poster, OPEN an existing approved poster/reel for that brand (`BrandAssets/{Brand}/{Platform}/*.html` or the `_remotion/src/*.tsx` consts) and copy the ACTUAL colors/fonts/masthead from it. If the doc table and the approved build conflict, the **live build wins** — then fix the doc table so it stops misleading the next session. For SM specifically: canonical palette/font note is now pinned in `live-ids.md` (electric blue `#2E7DF6`, NOT slate `#3F6F8E`; Big Shoulders Display going forward, Ep08/09 Fraunces serif is legacy).
2. **Brand voice & tone** drive the copy on the poster — match the brand, not a generic template.
3. **Proven design practice**: one dominant idea/focal point, strong hierarchy, generous whitespace. **Never overcrowd.** Just enough info to complement the post — not restate it.
3a. **⛔ MESSAGE-FIRST, attention-first — a poster is a 2-second scroll-stopper, NOT a slide of information (Joe corrected HARD, SM Ep04, June 2026).** Joe rejected a full SM batch that was on-brand and well-built because the posters were **dense and jargon-heavy with no single grabbing message** — *"there is no message in these posters just jargon and they have too much text, we need this to get people's attention not just to post."* The rules that emerged:
    - **The poster carries ONE big MESSAGE** — a single punchy human line, set large, that makes someone stop scrolling. That message IS the backbone (when Joe says "the message should be the backbone of every piece," he means the message is literally what's ON the art, big and clear — not buried).
    - **The CAPTION carries the detail, the stats, the jargon.** Do NOT put DSCR / SBA-7(a) / occupancy-% tables / multi-row myth lists / 4-step timelines / 3-stat-card grids ON the poster. Those are caption material. A poster crammed with them reads as a "slide," not a scroll-stopper.
    - **Minimal text + huge hierarchy.** One headline message, maybe one short supporting line, brand spine, done. If you're tempted to add a third text block, it belongs in the caption.
    - This does NOT kill structural variety (rule below) — vary the visual vocabulary across a batch, but EVERY poster stays message-first and sparse. A data-viz poster can still be ONE big number with one line; a dossier can be ONE bold finding, not a 5-row case file.
    - **⛔ MESSAGE-FIRST has TWO stages — plain is NOT enough; the message must be the BENEFIT/PAYOFF, not the problem or a concept (Joe corrected this on TOP of jargon, SI Ep016, July 2026).** Rule 3a kills jargon/density. This is the next gate: a headline can be perfectly plain English and STILL not convert because it describes the PROBLEM ("You spent the game on your phone") or states a CONCEPT ("Answer it once, let it answer itself") instead of the OUTCOME the viewer wants. Joe's exact words after a plain-but-not-converting batch: *"I still can't see the value of what is being talked about. If I can't understand it immediately it won't convert."* The half-second scroll test: does the headline PROMISE the reader something they want, or make them decode a situation? Fix = **benefit-led headline (what they GET/KEEP) as the hero, clever material demoted to PROOF underneath.** Worked swing: "You spent the game on your phone" → "Your business shouldn't cost you your kid's games"; "Answer it once, let it answer itself" → "Train it once. Your business runs without you"; "You hate the rate" → "Your time is worth more than you're charging for it" (+ the $100k test as proof below). Same family as INSIGHT-LEADS-STATS-SUPPORT and the benefit-CTA rule — make the reader SEE THE WIN first. ⛔ **STAGE 3 (Joe corrected a THIRD time, same SI Ep016 batch):** a benefit-led headline can STILL be clumsy written English — dangling tails ("worth more than you're charging for it"), vague pronouns ("Train it once"), clinical figures as the hook ("two-thirds of your day"), tacked-on "...Without the dread." fragments. After the benefit pass, read every headline ALOUD as a line a person would actually say and rewrite anything that doesn't parse as natural speech. The three stages compound (plain → benefit → sound) and ALL run when you first write the generator copy. Full rejected-vs-fixed set for all three stages (8 SI Ep016 headlines) lives in `successfulidiots-podcast` → "POSTER HEADLINE GLANCE-TEST → STAGE 2 → STAGE 3".
3b. **APPROVED COPY IS LOCKED across mediums — restyle changes LAYOUT, never WORDING (Joe corrected, June 2026).** When the ask is "another version / restyle / reformat / picture-book version / new medium" of copy that was already approved, the words stay VERBATIM; you change the layout/visual treatment to fit. Rewording approved lines to make them fit a new layout was rejected outright ("the wording should have remained the same"). If the layout truly can't hold the verbatim copy, resize/re-flow the LAYOUT (smaller type, more pages, tighter spacing) — do not trim or paraphrase the words. Pull the exact approved text from its source of record (Notion / the approved doc / the prior file) rather than retyping from memory.
3c. **⛔ A SOCIAL POSTER IS NOT AN EBOOK PAGE — and referencing another asset means learn its COPY, not copy its LAYOUT (Joe corrected HARD, SI Ep16 redo, July 2026).** When Joe points at a polished multi-page asset (e.g. the Storage 100 Picture Guide) as "how it should work," he means study its COPY CRAFT — one plain idea per line, warm, jargon-free, thoughts that build on each other — NOT reproduce its ebook furniture. I rebuilt SI social posters with lesson-number badges + "Lesson N / 8" labels + textbook chapter framing; vision-QA confirmed it read as a book page, and Joe rejected it: *"we are not creating the book, we are creating content. I just needed you to learn how to create the copy, not to mimic the style."* Rules: (a) a social poster keeps the normal brand social form (one bold message headline + one clean lead + optional bullets/callout, brand spine, footer) — NO lesson badges, NO "Lesson N of N", NO chapter/page model, NO cream-paper ebook layout on a social piece; (b) when the reference is another brand's asset, DEFAULT to learning the writing/clarity/flow and confirm if unsure — he almost never means copy the visual template; (c) the copy CAN carry the referenced clarity (short lines, builds on each other) while the LAYOUT stays a scroll-stopping social poster. Worked clean generator (no ebook furniture, content vertically centered): `_scripts/gen_si_ep016_v2.js`. The multi-page ebook layout is its OWN artifact class — only build it when the ask is literally an ebook/guide/PDF (see `references/multipage-ebook-pdf.md`), never as the default for social content.\n4. **Always visually QA** the rendered PNG before delivering — catch overflow/cutoff/overlap. (A $1.4M figure once overflowed the frame; caught at QA.) **Use `vision_analyze` with the PNG's file PATH directly** (e.g. `vision_analyze(image_url=r"C:\Users\somea\BrandAssets\...\idea1.png", question="QA: fonts loaded? overflow/overlap? footer clean?")`). Do NOT QA by pointing `browser_navigate`/`browser_vision` at the file — that returns the blank browser viewport, not the PNG (wasted a QA cycle this way, June 2026). `vision_analyze` on the path loads the actual rendered pixels.
5. **Footer byline = what Joe DOES, never vague adjectives — but Joe may want NO accreditation at all (corrected June 2026).** Concrete roles/work only — "CEO, Belrose Group · Founder, Storage Moguls" / "self-storage acquisitions · syndication · development" / "$29M+ acquired · $11M+ raised". NOT "operator · investor · builder" (those describe his AUDIENCE as much as him — Joe rejected them outright). **⛔ When Joe says "remove the accreditation / remove all accreditation," he means strip the ENTIRE credential byline (the `.footL` roster line) and keep ONLY the `joedowns.ai` mark** — do not leave a trimmed credit, do not substitute a softer one. He did exactly this on the origin-story poster (dropped "Host, Self Storage Investing podcast · $29M+ acquired" → footer = just `joedowns.ai`). This often pairs with removing a partner's NAME from the copy (e.g. "Scott Meyers" → "an email landed in my inbox") — when he's de-associating from the SSI partnership, the podcast-host credit usually goes too; if he removes the name but not explicitly the credit, ASK whether the "Host, Self Storage Investing podcast" line should also come off. "The Real Reps" CTA is OFF by default (newsletter-fit posts only). Full rule: `references/jd-design-system.md`.
6. **HUMANIZE the text baked INTO the poster, not just the caption (Joe directive, June 2026).** Joe's no-AI-tells rule extends to the words ON the visual: *"remember to humanize even the texts in posters."* Before rendering, scrub the baked-in copy for the same tells the `humanizer` skill targets — **em-dashes (both literal `—` AND the `&mdash;` HTML entity — grep BOTH), the `·`/`&middot;` separators where they read as a tell, `&` for "and", and "not X, it's Y" parallelism.** Recast em-dashes as commas/periods/colons (a list item "Bad debt — how well…" reads cleanly as "Bad debt: how well…"). PRESERVE the brand voice (Joe's punchy declaratives stay). Fixing the SOURCE html also quietly improves the already-built feed PNG since it's the same file — Joe approved fixing the source ("do what you recommend") even though the feed posters were "done," because the story re-render touches the file anyway. Scope note: this applies going FORWARD (new renders / story versions); don't bulk-re-render finished uploaded posters just to de-em-dash them unless you're regenerating them for another reason.

## Match visual STYLE to the copy's energy (Joe directive, June 2026)
When making a PAIR/BATCH of posters for one episode, don't just vary the layout —
pair each poster's aesthetic to its copy's emotional register, and make the pair
visibly different to prove range (Joe: "not the same static type of image every
time"):
- **LOUD / punchy / absurd-hook copy** → SI neo-brutalist sticker-pop (saturated
  yellow, hard borders, offset shadows, object hero). Proven: SI Ep030 "squeaky
  chair" poster.
- **QUIET / reflective / payoff copy** → SI dark CASE FILE dossier (near-black,
  Space Mono labels, green FINDING border). Proven: SI Ep030 "cappuccino" poster.
Two distinct copy devices + two distinct visual systems across one pair = the
range Joe wants. Neither needed the host characters (correct — they're optional).
Copy craft itself lives in `successfulidiots-podcast` →
`references/narrative-copy-strategy.md` (the narrative strategy that drives which
energy a poster should match).

### Sticker-pop pitfall — highlighted word box overlaps the headline lines
A green/inverse highlight span inside an Oswald caps headline collides with the
lines above/below it when `line-height` is tight (`0.97`). The colored box eats
into neighboring lines. FIX = headline `line-height ≈ 1.18` + on the highlight
span add `box-decoration-break:clone` (+ `-webkit-` prefix) and a little vertical
padding so the box wraps cleanly. Hit + fixed on the SI Ep030 squeaky-chair
poster; always vision-QA a highlighted headline word for this specifically.

### Absolute-position pitfall — a `top:`-pinned block overlaps a multi-line headline (recurs)
With the batch generator pattern (each element absolutely positioned by a fixed
`top:`), a headline sized for N lines that actually wraps to N+1 silently runs
UNDER the next block (cards / steps / body), hiding a whole line. Caught on the
SI Ep030 "prompt-vs-system" poster — line 3 "ANYTHING WITH IT" sat behind the
two cards. FIX = budget the headline band for the REAL wrapped line count: drop
the headline `font-size` and push the following block's `top:` down so it clears
(e.g. headline 82→68px, cards `top:` 430→530px). This is the cost of absolute
positioning — it does not reflow. ALWAYS vision-QA every absolutely-positioned
poster for a block sitting on top of the headline's last line, especially long
headlines. (A flexbox/normal-flow column avoids this entirely; use absolute
`top:` only when you've eyeballed the wrap.)

## STRUCTURAL visual variety — "style range" is NOT enough (Joe corrected HARD, June 2026)
Joe rejected an SI Ep030 batch of 5 posters that were on-brand, well-built, and used different colors/layouts — because they were **all the same SPECIES: big text on a background.** His exact note: *"they are all text and all just looking the same… there's no variety in the elements within the posters."* Different colors + different arrangements of TYPE is NOT variety. Real variety means different **visual vocabularies** across a batch:
- **Visual metaphor / illustration** — *show* the idea with drawn objects (an envelope escaping a SPAM box into an INBOX), not type. 
- **Real data-viz** — an actual chart where SCALE carries the message (a stubby 1× bar vs a towering 24× bar), not the word "24X" set big.
- **Photographic / character hero** — real host photos or the SI character cutouts as the focal element; imagery carries it.
- **Icon / diagram / flow** — symbols, numbered process, before/after. ⚠️ Drawn node/flow diagrams fail silently if you don't engineer the read (Joe rejected a muddy "prompt vs system" node-diagram, June 2026): arrows must sit in the GAPS between nodes (never buried inside them), one clean left-to-right axis (no zig-zag), the metaphor's meaning as the visible variable (steadily growing nodes = compounding), and an explicit dashed feedback loop for any "it feeds itself" idea. Full recipe + the 4 clarity failures: `references/svg-diagram-legibility.md`.
- Pure typographic layouts are ONE family — use at most 1–2 in a batch, not the whole set.
Rule: in a multi-poster batch, **no two posters should share a structure.** A reader scrolling should see distinct *kinds* of images, not the same card reskinned.

> **⛔ PRE-RENDER GUARD — the batch-generator trap has bitten TWICE now (SI Ep030, SM Ep001). Run this BEFORE rendering any batch.** The failure mode: writing ONE shared skeleton (a single `.wrap`/`.stage` with masthead → headline → content, top-anchored) and swapping only the inner text per idea → every poster is the same species with an empty lower half. To prevent it:
> 1. **Name the vocabulary for each piece FIRST**, from the understanding (line-graph / metaphor object / real data-viz / dossier / calendar-or-icon motif / typographic quote / photo). Write them in a list. If two adjacent pieces share a vocabulary, change one.
> 2. **Give each piece its OWN composition**, not one shared `.stage` skeleton with swapped text. The shared part is ONLY the brand spine (bg, masthead, footer, type scale, margins) — the focal treatment must differ structurally.
> 3. **Vary the anchor.** Not everything top-pinned. Use centered, vertically-centered, bottom-anchored, split. A poster with content in the top third and a bare navy lower half is the tell — close it (enlarge hero / add the motif) or re-anchor.
> 4. **Vision-QA the batch AS A SET**, asking "do these look like the same card reskinned?" — not just each one alone. If yes, it failed; rebuild before delivering.


### EVERY piece gets its OWN visual, and YOU assign the vocabulary — don't ask (Joe, locked, corrected repeatedly June 2026)
Two locked rules Joe is tired of repeating ("did you save this to memory? do I have to keep reminding you?"):
- **EVERY content piece in a batch gets its own visual — not just "lead" pieces, not a subset.** 18 pieces → 18 visuals. Do NOT ask Joe how many; the answer is always "all of them."
- **Match the format to each piece YOURSELF, from the UNDERSTANDING — don't ask Joe to assign vocabularies.** Joe: "you have the understanding so you should be able to know what visual suits what." The mapping is your job: loud/absurd-hook → sticker-pop; quiet/payoff → dark CASE FILE dossier; a single number/stat → big-number or real data-viz; a method/process → numbered infographic; a mantra/one-liner → typographic quote; an episode/host promo → character or real host-photo. Characters stay in the MINORITY. Compose each to its theme (not a template). These are SETTLED — execute, don't re-litigate them with a clarify question.

### Ground every poster in NAMED design principles — don't "throw things on a canvas"
Joe's follow-up correction: the first illustrated attempts were better but still felt scattered — *"use proper design principles, not just throwing things there."* Before rendering, engineer these in (canonical set: hierarchy, dominance, balance, contrast, alignment, proximity, scale, unity, active whitespace). Concrete checklist + the per-family worked examples (spam→inbox metaphor, 24× chart, character-hero figure/ground panel) live in **`references/design-principles-checklist.md`** — read it for any from-scratch illustrated poster or multi-style batch. Key moves that fixed the scattered look: ONE dominant focal point per poster; elements share a real grid/baseline (no eyeballed placement); dramatic intentional SCALE contrast; related items grouped with whitespace separating groups; a shared margin+type system across the batch so it reads as a FAMILY (unity).

### Cutout pitfall — a WIDE chest-up cutout fights a tall (4:5/9:16) canvas (NEW, June 2026)
The SI duo cutout `SI_char_duo_at_mic_T.png` is ~963×581 (WIDER than tall, framed chest-up — its bottom edge is a flat horizontal crop). Forcing it into a 1080×1350 portrait creates two failure modes Joe caught:
- Sized small + floated mid-canvas → its flat bottom reads as "a hard line cutting across them / chopped torso," AND leaves a big empty void above.
- Sized to fill height → it collides with the headline/footer.
What actually works: **sit the flat-crop cutout FLUSH to the canvas bottom (`bottom:0`) and scale it LARGE (~760–820px wide) so it occupies the whole lower ~third-to-half** — the flat base then reads as figures "emerging from the bottom edge" (a normal convention), not chopped. Add a soft radial brand-color ground-glow behind it so it doesn't float on flat color. Keep ALL footer text/divider on the opposite side (left) so nothing crosses the art. HONEST residual: a wide chest-up crop in a tall frame still tends to leave some empty band above the figures — accept it as breathing room, or close it by enlarging the characters / adding one supporting element; don't pretend it's gone. The deeper rule: **match the cutout's native aspect ratio to the layout zone — don't jam a wide short asset into a tall slot and tune endlessly.**

### Cutout pitfall — a full-width footer/divider RULE draws straight across a character (NEW, June 2026)
When a character cutout is anchored at the bottom and the footer has a full-width `border-top` (or any edge-to-edge rule), the line draws **across the character's body** and looks like a seam slicing through them — Joe caught it ("was the line cutting across them a mistake?"). It's a mistake, not a style. FIX = either (a) confine the divider to the text zone only (`border-top:none` on `.foot` + a `::before` bar with a fixed `width` that stops before the art), or preferably BOTH that AND (b) give the character a higher `z-index` than the footer rule so it can never be crossed. Always vision-QA where any full-width line passes behind a cutout.

## Characters are an OPTIONAL style asset — NOT a default (Joe's directive, locked June 2026)
The illustrated host characters (SI Joe+Peter) exist to give the feed **more than one style of poster** — they are ONE option in the rotation, NOT required in every design. Joe explicitly tested this: "these characters don't have to be in every design." So:
- **Most pieces in a batch should be character-FREE.** Lead with the full style range (minimalist, big-stat, dossier, typographic quote, infographic, list card, concept). Drop a character in ONLY where it genuinely adds something (an episode/host promo, a punchy host-voice line).
- Rule of thumb from the passing test: in a 10-visual batch, ~2 used characters, 8 did not. Reflexively putting characters on everything is the failure mode, not the goal.
- When you DO use them, use the clean transparent cutouts (`scripts/gemini_char_cutout.py` output) so they composite with no green box / no halo.

## PRESENTING a finished batch to Joe — ONE PIECE PER MESSAGE, content+visual TOGETHER (Joe corrected 4× in one session, June 2026)

How you DELIVER a batch for review is a locked rule, separate from how you build it. Joe rejected, in order, several wrong presentations of the SI Ep030 set before it landed — this is the single most-repeated correction of the session, so start already knowing it:
- ❌ All copy first, then all visuals (a list of captions, then the images) — \"I said content + visual in the same message.\"
- ❌ Posting a few pieces, then a separator, then more — \"content and visual in same message then go [to] the next.\"
- ❌ One giant message with every piece + every image stacked.
- ✅ **ONE PIECE PER MESSAGE: that piece's caption immediately followed by its `MEDIA:` image, formatted exactly as Joe would post it — then STOP and wait for \"next\" (or 👍).** Roll to the next piece only when he says so. \"The same way I would be posting.\"

### Fixing a WASHED-OUT / dull photo (grading recipe — order matters)

  3. `ImageEnhance.Contrast ≈1.10`, `Color ≈1.16`, `Brightness 1.0`.
  4. `ImageFilter.UnsharpMask(radius≈2.0, percent≈110, threshold=2)`.
